Actúa como un Documentador de Software experto. Tu tarea es generar un archivo **README.md** profesional, exhaustivo y bien estructurado para el repositorio actual.

**INSTRUCCIONES CLAVE:**

1.  **Análisis Completo:** Analiza todo el contenido, el propósito y la estructura del proyecto en este directorio.
2.  **Lenguaje y Tono:** La documentación debe estar escrita íntegramente en **inglés**, utilizando un tono **profesional y explicativo**.
3.  **Estructura del README:** El README debe incluir al menos las siguientes secciones de forma clara y con encabezados de Markdown:
    * **Title/Logo:** Un título conciso y relevante (y una sugerencia de logo si aplica).
    * **Project Overview:** Una descripción de alto nivel del propósito y funcionalidad del proyecto.
    * **Features:** Puntos clave de lo que hace el proyecto.
    * **Getting Started:** Instrucciones detalladas de instalación y configuración.
    * **File Structure/Tree:** Muestra el árbol de archivos relevante del proyecto, explicando brevemente la función de los directorios clave.
    * **Configuration/Data:** Indica qué archivos y datos deben rellenarse/configurarse para que el proyecto funcione (ejemplos de variables de entorno, *placeholders* en archivos de configuración).
    * **Usage/Examples:** Ejemplos claros de cómo usar la aplicación o las funciones principales.
    * **Diagrams (Visuals):** Incluye *placeholders* para los gráficos solicitados.

4.  **Generación de Gráficos (Placeholders):**
    * Incluye un bloque de texto que represente el **System Workflow Diagram** (Diagrama de flujo de trabajo del sistema).
    * Incluye un bloque de texto que represente el **Diagram Walkthrough** (Recorrido del Diagrama/Funcionamiento).
    * **Nota:** El agente debe **describir conceptualmente** estos diagramas, explicando qué elementos contendrían y cómo se relacionarían, ya que el agente no puede generar imágenes reales.

5.  **Revisión y Actualización:** Sobrescribe/reemplaza el archivo `README.md` existente con el contenido generado. Asegura que la documentación esté completa, sea precisa y esté alineada con el código actual.
