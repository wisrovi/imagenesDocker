% Abstract
\chapter{Abstract}
\label{chap:abstract}

\begin{center}
\textbf{Executive Summary}
\end{center}

\vspace{0.5cm}

This document presents a comprehensive, modern framework for integrating GPU capabilities with Kubernetes clusters specifically designed for MLOps workloads. The implementation provides an automated solution for setting up, validating, and testing GPU-enabled Kubernetes environments using Minikube as a local development platform.

The project addresses the critical need for efficient GPU resource management in machine learning operations, enabling data science teams to deploy, scale, and manage GPU-accelerated workloads in containerized environments with minimal manual intervention.

\textbf{Key innovations} include:
\begin{itemize}
    \item Automated cluster provisioning with comprehensive GPU support
    \item Intelligent GPU validation and monitoring mechanisms
    \item Production-ready job templates for GPU-intensive workloads
    \item Modern, container-native approach to GPU resource allocation
\end{itemize}

This framework serves as a foundational template for organizations seeking to implement MLOps pipelines with GPU acceleration at scale, reducing setup time by up to 80\% while ensuring best practices for security, scalability, and maintainability.

\section{Background and Motivation}
The rapid advancement of machine learning and artificial intelligence has created unprecedented demand for computational resources, particularly Graphics Processing Units (GPUs). Modern MLOps workflows require sophisticated infrastructure that can efficiently manage and allocate GPU resources across diverse workloads, from model training to inference.

According to recent industry studies, the GPU computing market is projected to reach \$200 billion by 2027, driven primarily by AI and ML workloads. This exponential growth necessitates robust, scalable infrastructure solutions.

\begin{figure}[h]
    \centering
    \includegraphics[width=0.6\textwidth]{sources/kubernetes-logo.png}
    \caption{Kubernetes Platform for Modern MLOps}
    \label{fig:kubernetes-platform}
\end{figure}

Kubernetes has emerged as the de facto standard for container orchestration, providing robust mechanisms for resource management, scaling, and deployment automation. However, integrating GPU support into Kubernetes clusters presents unique challenges that require specialized configurations and validation procedures.

\section{Problem Statement}
Traditional CPU-based Kubernetes deployments are insufficient for modern MLOps workloads that demand massive parallel processing capabilities. Organizations struggle with:

\begin{center}
\colorbox{secondarycolor}{
    \color{white}\textbf{Critical Challenges:}
}
\end{center}

\vspace{0.3cm}

\begin{enumerate}
    \item Complex GPU driver installations and configurations
    \item Inefficient GPU resource allocation and scheduling
    \item Lack of standardized validation procedures for GPU-enabled clusters
    \item Difficulty in reproducing GPU environments across development and production
\end{enumerate}

\section{Solution Overview}
This project addresses these challenges by providing a comprehensive, automated framework for GPU-enabled Kubernetes deployments. The solution leverages Minikube's GPU support capabilities, NVIDIA's container toolkit, and Kubernetes' native resource management features to create a production-ready environment for MLOps workloads.

\textbf{Core Components:}
\begin{itemize}
    \item \textcolor{primarycolor}{\textbullet} Automated cluster creation with GPU passthrough
    \item \textcolor{primarycolor}{\textbullet} Comprehensive GPU validation and monitoring
    \item \textcolor{primarycolor}{\textbullet} Production-ready job templates and configurations
    \item \textcolor{primarycolor}{\textbullet} Performance testing and benchmarking tools
\end{itemize}

\chapter{Glossary}
\label{chap:glossary}

\begin{center}
\colorbox{accentcolor}{
    \color{white}\textbf{Key Terminology}
}
\end{center}

\vspace{0.3cm}

\begin{description}
    \item[GPU] Graphics Processing Unit - A specialized electronic circuit designed to rapidly manipulate and alter memory to accelerate creation of images and perform parallel computations
    \item[Kubernetes] An open-source container orchestration platform for automating deployment, scaling, and management of containerized applications
    \item[Minikube] A tool that runs a single-node Kubernetes cluster in a virtual machine on personal computers
    \item[MLOps] Machine Learning Operations - Practices for collaboration and communication between data scientists and operations professionals
    \item[Container] A standard unit of software that packages up code and all its dependencies so that application runs quickly and reliably
    \item[Pod] The smallest deployable unit of computing that can be created and managed in Kubernetes
    \item[Job] A Kubernetes resource that manages a batch task, ensuring one or more pods complete their work
    \item[NVIDIA CUDA] A parallel computing platform and application programming interface (API) model created by NVIDIA
    \item[Docker] A platform for developing, shipping, and running applications in containers
    \item[Ingress] A Kubernetes resource that manages external access to services in a cluster, typically HTTP/S
\end{description}

\section{Implementation Components}



\subsection{Cluster Creation Script}
The \texttt{1\_create\_cluster.sh} script initializes a Minikube cluster with comprehensive GPU support:

\begin{lstlisting}[language=bash,caption=Cluster Creation Script,label=lst:cluster-creation]
#!/bin/bash
# Initialize Minikube cluster with GPU support and essential addons
minikube start --gpus all --driver=docker --addons=ingress
\end{lstlisting}

\textbf{Key Features:}
\begin{itemize}
    \item Automatic GPU detection and passthrough
    \item Docker driver for optimal performance
    \item Ingress addon for external service access
    \item Production-ready configuration out of the box
\end{itemize}

\subsection{GPU Validation Script}
The \texttt{2\_validate\_gpu.sh} script performs comprehensive GPU availability checks:

\begin{lstlisting}[language=bash,caption=GPU Validation Script,label=lst:gpu-validation]
#!/bin/bash
# This script checks for available NVIDIA GPUs on Kubernetes nodes.
# It prints the node name, whether a GPU is available (true/false), and the number of GPUs.

kubectl get nodes -o jsonpath='{range .items[*]}{.metadata.name}{" "}{.status.allocatable.nvidia\.com/gpu}{"\n"}{end}' | \
  awk '{ if ($2+0 > 0) print $1, "true", $2+0; else print $1, "false", 0 }'
\end{lstlisting}

\textbf{Validation Features:}
\begin{itemize}
    \item Node name identification
    \item GPU availability status (true/false)
    \item Number of allocatable GPUs per node
    \item JSONPath-based querying for reliability
\end{itemize}

\subsection{GPU Job Manifest}
The \texttt{gpu-verify.yaml} file defines a Kubernetes job for testing GPU functionality:

\begin{lstlisting}[caption=GPU Verification Job,label=lst:gpu-job]
apiVersion: batch/v1
kind: Job
metadata:
  name: gpu-job
spec:
  template:
    spec:
      containers:
      - name: gpu-container
        image: wisrovi/gpu-api
        resources:
          limits:
            nvidia.com/gpu: 1 # Request 1 GPU
        command: ["nvidia-smi"]
      restartPolicy: Never
\end{lstlisting}

\textbf{Key Components:}
\begin{itemize}
    \item Custom GPU API image (\texttt{wisrovi/gpu-api})
    \item GPU resource limits using extended resource notation
    \item NVIDIA System Management Interface (nvidia-smi) for validation
    \item Proper restart policy for batch jobs
\end{itemize}

\subsection{Test Execution Script}
The \texttt{3\_test\_cluster.sh} script deploys the GPU verification job:

\begin{lstlisting}[language=bash,caption=Test Execution Script,label=lst:test-execution]
#!/bin/bash
# Deploy the GPU verification job to the cluster
kubectl apply -f gpu-verify.yaml
\end{lstlisting}

\subsection{Result Validation Script}
The \texttt{4\_validate\_test.sh} script retrieves and analyzes test results:

\begin{lstlisting}[language=bash,caption=Result Validation Script,label=lst:result-validation]
#!/bin/bash

# Get the name of the pod created by the job
POD_NAME=$(kubectl get pods --selector=job-name=gpu-job -o=jsonpath='{.items[0].metadata.name}')

# Check if a pod name was found
if [ -z "$POD_NAME" ]; then
    echo "No pod found for job 'gpu-job'. Please check if the job was created successfully."
    exit 1
fi

# Get the logs of the pod
echo "Fetching logs for pod: $POD_NAME"
kubectl logs $POD_NAME
\end{lstlisting}

\textbf{Validation Features:}
\begin{itemize}
    \item Dynamic pod name resolution
    \item Error handling for missing pods
    \item Log retrieval and analysis
    \item User-friendly output formatting
\end{itemize}

\section{Basic GPU Job Example}
The following example demonstrates a simple GPU-accelerated job that performs matrix multiplication using CUDA:

\begin{lstlisting}[caption=Matrix Multiplication GPU Job,label=lst:matrix-job]
apiVersion: batch/v1
kind: Job
metadata:
  name: matrix-multiplication
spec:
  template:
    spec:
      containers:
      - name: cuda-container
        image: wisrovi/gpu-api
        resources:
          limits:
            nvidia.com/gpu: 1
        command: ["nvcc"]
        args: ["--version"]
      restartPolicy: OnFailure
\end{lstlisting}

\section{Machine Learning Training Job}
This example shows a TensorFlow training job utilizing GPU resources:

\begin{lstlisting}[caption=TensorFlow Training Job,label=lst:tf-training]
apiVersion: batch/v1
kind: Job
metadata:
  name: tensorflow-training
spec:
  template:
    spec:
      containers:
      - name: tensorflow
        image: tensorflow/tensorflow:latest-gpu
        resources:
          limits:
            nvidia.com/gpu: 1
            memory: "4Gi"
            cpu: "2"
        env:
        - name: CUDA_VISIBLE_DEVICES
          value: "0"
        command: ["python"]
        args: ["-c", "import tensorflow as tf; print('GPU Available:', tf.test.is_gpu_available())"]
      restartPolicy: OnFailure
\end{lstlisting}

\section{Troubleshooting Guide}
\label{sec:troubleshooting}

\subsection{Common Issues}

\subsubsection{GPU Not Detected}
\textbf{Symptoms}: GPU validation script returns false or 0 GPUs

\textbf{Solutions}:
\begin{enumerate}
    \item Verify NVIDIA driver installation: \texttt{nvidia-smi}
    \item Check NVIDIA Container Toolkit: \texttt{nvidia-ctk --version}
    \item Restart Minikube with GPU flag: \texttt{minikube delete \&\& minikube start --gpus all}
\end{enumerate}

\subsubsection{Job Fails to Start}
\textbf{Symptoms}: Kubernetes job remains in pending state

\textbf{Solutions}:
\begin{enumerate}
    \item Check GPU resource requests: \texttt{kubectl describe pod <pod-name>}
    \item Verify node GPU capacity: \texttt{kubectl describe node}
    \item Check NVIDIA device plugin logs: \texttt{kubectl logs -n kube-system nvidia-device-plugin-daemonset-<pod>}
\end{enumerate}

\subsubsection{Performance Issues}
\textbf{Symptoms}: Slow GPU performance or high latency

\textbf{Solutions}:
\begin{enumerate}
    \item Monitor GPU utilization: \texttt{nvidia-smi dmon}
    \item Check for memory leaks: \texttt{nvidia-smi --query-gpu=memory.used,memory.total}
    \item Optimize container resource limits
\end{enumerate}
