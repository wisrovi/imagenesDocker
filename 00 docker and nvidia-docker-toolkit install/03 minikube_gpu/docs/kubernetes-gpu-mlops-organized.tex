\section{Background and Context}
The exponential growth of machine learning and artificial intelligence applications has fundamentally transformed computational requirements across industries. Modern MLOps workflows now demand access to specialized hardware, particularly Graphics Processing Units (GPUs), which provide the parallel processing power essential for training complex neural networks and running inference at scale. This paradigm shift has created significant infrastructure challenges as organizations struggle to effectively integrate GPU capabilities with container orchestration platforms.

Traditional deployment approaches often fail to address the unique requirements of GPU-accelerated workloads, leading to inefficient resource utilization, complex management overhead, and inconsistent environments across development and production stages. The need for a standardized, automated solution has become increasingly critical as organizations scale their ML operations.

\section{Problem Statement and Technical Challenges}
Conventional CPU-based Kubernetes deployments are fundamentally inadequate for modern MLOps workloads that require massive parallel processing capabilities. Organizations implementing GPU-accelerated machine learning pipelines encounter several critical technical and operational challenges that impede productivity and increase operational complexity:

\begin{center}
\colorbox{secondarycolor}{
    \color{white}\textbf{Critical Technical Challenges:}
}
\end{center}

\vspace{0.3cm}

\begin{enumerate}
    \item \textbf{Complex GPU Driver Management}: Installing and maintaining compatible GPU drivers across different operating systems and hardware configurations requires specialized expertise and frequent updates
    \item \textbf{Inefficient Resource Allocation}: Traditional schedulers lack awareness of GPU-specific requirements, leading to suboptimal resource utilization and potential resource conflicts
    \item \textbf{Validation Complexity}: Ensuring GPU functionality within containerized environments requires comprehensive testing procedures that are often overlooked in standard deployment pipelines
    \item \textbf{Environment Reproducibility}: Creating consistent GPU-enabled environments across development, testing, and production stages presents significant technical hurdles due to hardware and software dependencies
\end{enumerate}

\section{Proposed Solution and Technical Approach}
This project addresses these multifaceted challenges through a comprehensive, automated framework that systematically integrates proven technologies and best practices. Our solution leverages a carefully selected technology stack designed to provide maximum compatibility, performance, and ease of use:

\begin{itemize}
    \item \textbf{Minikube's GPU Support Capabilities}: Utilizes Minikube's native GPU passthrough functionality to create local development environments that accurately mirror production configurations
    \item \textbf{NVIDIA's Container Toolkit}: Implements NVIDIA's industry-standard container toolkit to ensure seamless GPU access within containerized applications
    \item \textbf{Kubernetes Native Resource Management}: Extends Kubernetes' powerful resource management features to handle GPU-specific scheduling and allocation requirements
    \item \textbf{Production-Ready Job Templates}: Provides comprehensive, battle-tested job templates specifically designed for GPU-intensive workloads with built-in optimization and monitoring capabilities
\end{itemize}

\section{Detailed Component Analysis}
\subsection{Infrastructure Layer: Foundation of GPU Computing}
The infrastructure layer forms the bedrock of our GPU-enabled Kubernetes environment, providing essential containerization and virtualization capabilities. This layer combines Docker's proven container runtime technology with Minikube's sophisticated cluster management capabilities to create a robust foundation for GPU-accelerated workloads.

Docker serves as the container runtime, providing lightweight, portable packaging for applications and their dependencies. It ensures consistent execution environments across different computing platforms while maintaining high performance and resource efficiency. Docker's mature ecosystem and extensive tooling support make it an ideal choice for production deployments.

\begin{figure}[h]
    \centering
    \includegraphics[width=0.5\textwidth]{sources/docker-logo.png}
    \caption{Docker Container Platform}
    \label{fig:docker-platform}
\end{figure}

Minikube complements Docker by providing a complete, single-node Kubernetes cluster that runs locally on the developer machine. It includes built-in support for GPU passthrough, enabling developers to create production-like environments without requiring access to full-scale infrastructure. Minikube's intelligent resource management and automatic configuration capabilities significantly reduce the complexity of setting up GPU-enabled clusters.

\subsection{Orchestration Layer: Intelligent Resource Management}
The orchestration layer leverages Kubernetes' powerful container management capabilities to provide intelligent scheduling, resource allocation, and lifecycle management for GPU-accelerated workloads. This layer extends Kubernetes' native functionality through specialized components designed specifically for GPU resource management.

Kubernetes manages container deployment, scaling, and operations, providing automated rollouts and rollbacks, service discovery, and load balancing. Its declarative configuration model enables infrastructure as code practices, ensuring consistency and reproducibility across environments.

The NVIDIA device plugin serves as a critical bridge between Kubernetes' resource management framework and the underlying GPU hardware. It extends the Kubernetes scheduler to recognize GPU resources as first-class citizens, enabling intelligent placement decisions based on GPU availability, capacity, and workload requirements. This integration ensures optimal resource utilization and prevents resource conflicts.

\section{Docker Installation and Configuration}
Docker serves as the container runtime for our GPU-enabled Kubernetes environment.

\subsection{Docker Engine Installation}
\begin{lstlisting}[language=bash,caption=Docker Installation Ubuntu,label=lst:docker-install]
# Remove old Docker versions
sudo apt-get remove docker docker-engine docker.io containerd runc

# Add Docker's official GPG key
sudo apt-get update
sudo apt-get install -y ca-certificates curl gnupg
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg

# Set up the repository
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# Install Docker Engine
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# Add user to docker group
sudo usermod -aG docker $USER
\end{lstlisting}

\subsection{NVIDIA Container Toolkit Installation}
The NVIDIA Container Toolkit enables Docker to utilize GPU resources within containers.

\begin{lstlisting}[language=bash,caption=NVIDIA Container Toolkit Installation,label=lst:nvidia-ctk]
# Add NVIDIA Container Toolkit repository
curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey | sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg
curl -s -L https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list | \
  sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' | \
  sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list

# Update package list and install toolkit
sudo apt-get update
sudo apt-get install -y nvidia-container-toolkit

# Configure Docker to use NVIDIA runtime
sudo nvidia-ctk runtime configure --runtime=docker

# Restart Docker to apply changes
sudo systemctl restart docker
\end{lstlisting}

\section{Troubleshooting Common Installation Issues}
\subsection{Driver Installation Problems}
\textbf{Issue}: NVIDIA driver installation fails
\begin{itemize}
    \item Ensure system meets minimum requirements
    \item Disable secure boot in BIOS/UEFI
    \item Remove existing NVIDIA drivers: \texttt{sudo apt-get purge nvidia-*}
    \item Reboot before attempting reinstallation
\end{itemize}

\subsection{Docker GPU Access Issues}
\textbf{Issue}: Docker cannot access GPU resources
\begin{itemize}
    \item Verify NVIDIA Container Toolkit installation
    \item Check Docker runtime configuration: \texttt{sudo docker info | grep nvidia}
    \item Restart Docker service: \texttt{sudo systemctl restart docker}
    \item Verify user permissions for Docker access
\end{itemize}

\subsection{Minikube GPU Detection Issues}
\textbf{Issue}: Minikube doesn't detect GPU
\begin{itemize}
    \item Ensure NVIDIA drivers are properly installed
    \item Check Docker GPU functionality first
    \item Use correct Minikube driver: \texttt{--driver=docker}
    \item Verify GPU passthrough: \texttt{minikube start --gpus all}
\end{itemize}

\section{Comprehensive GPU Validation and Verification}
Robust GPU validation is essential for ensuring reliable operation of GPU-accelerated workloads. Our validation framework performs multiple checks to verify GPU availability, functionality, and proper integration with the Kubernetes scheduler.

\begin{lstlisting}[language=bash,caption=Advanced GPU Validation Script,label=lst:gpu-validation]
#!/bin/bash
# Comprehensive validation of NVIDIA GPU availability and functionality
kubectl get nodes -o jsonpath='{range .items[*]}{.metadata.name}{" "}{.status.allocatable.nvidia\.com/gpu}{"\n"}{end}' | \
  awk '{ if ($2+0 > 0) print $1, "true", $2+0; else print $1, "false", 0 }'
\end{lstlisting}

This validation script provides detailed information about:
\begin{itemize}
    \item Node identification and GPU availability status
    \item Quantitative GPU resource allocation per node
    \item JSONPath-based querying for reliable and consistent results
    \item Error handling for malformed responses or missing data
\end{itemize}

The validation output can be easily parsed by monitoring systems and integrated into CI/CD pipelines for automated verification.

\section{GPU Workload Deployment and Management}
GPU workloads are deployed using standardized Kubernetes job templates that incorporate best practices for resource management, security, and monitoring. These templates ensure consistent behavior across different environments and simplify the deployment process for data science teams.

\begin{lstlisting}[caption=Production-Ready GPU Job Template,label=lst:gpu-job]
apiVersion: batch/v1
kind: Job
metadata:
  name: gpu-job
  labels:
    app: gpu-workload
    environment: production
spec:
  template:
    metadata:
      labels:
        app: gpu-workload
    spec:
      containers:
      - name: gpu-container
        image: wisrovi/gpu-api
        resources:
          limits:
            nvidia.com/gpu: 1
            memory: "4Gi"
            cpu: "2"
          requests:
            nvidia.com/gpu: 1
            memory: "2Gi"
            cpu: "1"
        command: ["nvidia-smi"]
        env:
        - name: CUDA_VISIBLE_DEVICES
          value: "0"
      restartPolicy: Never
  backoffLimit: 3
\end{lstlisting}

This template includes several important production considerations:
\begin{itemize}
    \item \textbf{Resource Requests and Limits}: Ensures fair resource allocation while preventing resource starvation
    \item \textbf{Environment Variables}: Configures CUDA device visibility for optimal performance
    \item \textbf{Restart Policies}: Implements appropriate retry logic for batch workloads
    \item \textbf{Metadata and Labels}: Enables proper resource tracking and management
\end{itemize}

\section{Troubleshooting Guide}
\subsection{Common Issues}
\textbf{GPU Not Detected:}
\begin{itemize}
    \item Verify NVIDIA driver installation: \texttt{nvidia-smi}
    \item Check NVIDIA Container Toolkit: \texttt{nvidia-ctk --version}
    \item Restart Minikube with GPU flag
\end{itemize}

\textbf{Job Fails to Start:}
\begin{itemize}
    \item Check GPU resource requests: \texttt{kubectl describe pod <pod-name>}
    \item Verify node GPU capacity: \texttt{kubectl describe node}
    \item Check NVIDIA device plugin logs
\end{itemize}
