# Milvus Vector Database Project

This project provides a comprehensive Docker Compose setup to run a standalone instance of Milvus, along with all its necessary dependencies, a full monitoring stack, and a suite of Python scripts for demonstrating CRUD operations.

## 1. What is Milvus?

Milvus is an open-source vector database built for AI applications. It's designed to store, index, and manage massive embedding vectors generated by deep learning models. Its core purpose is to enable similarity search (also known as vector search or nearest neighbor search) at scale.

*(For a more detailed explanation of Milvus concepts, architecture, and its comparison with other database types, please refer to the Appendix at the end of this document.)*

## 2. Getting Started

This section guides you through setting up and running the entire Milvus environment.

### Prerequisites

- **Docker:** [Installation Guide](https://docs.docker.com/get-docker/)
- **Docker Compose:** [Installation Guide](https://docs.docker.com/compose/install/)
- **Python 3.x** and **pip**

### Starting the Environment

To start all services in detached mode, navigate to the `docker` directory and run:

```bash
cd docker
docker-compose up -d
```

### Verifying the Services

Check the status of the containers to ensure all services are `Up` and `(healthy)`:

```bash
docker-compose ps
```

### Accessing Services

Once the environment is running, you can access the different services through the following ports on your `localhost`:

| Service           | URL                               | Credentials                 | Purpose                               |
|-------------------|-----------------------------------|-----------------------------|---------------------------------------|
| **Milvus SDK**    | `localhost:19530`                 | -                           | For Python clients to connect to Milvus |
| **Attu (UI)**     | `http://localhost:8000`           | -                           | Web-based Management UI for Milvus    |
| **Grafana**       | `http://localhost:3000`           | `admin` / `admin` (default) | Metrics Visualization & Dashboards    |
| **Prometheus**    | `http://localhost:9090`           | -                           | Metrics Collection                    |
| **Minio Console** | `http://localhost:9002`           | `minioadmin` / `minioadmin` | Web UI for the Object Storage         |
| **Minio API**     | `localhost:9100`                  | `minioadmin` / `minioadmin` | API endpoint for the Object Storage   |

### Stopping the Environment

To stop all running services, use:

```bash
docker-compose down
```
This will stop and remove the containers, but the data stored in the `volumes` directory will be preserved.

### Viewing Logs

You can view the logs for a specific service using its container name. For example, to check the logs for the Milvus standalone service:

```bash
docker-compose logs -f standalone
```

## 3. Python Scripts: CRUD Demo

This project includes a set of Python scripts to demonstrate basic Create, Read, Update, and Delete (CRUD) operations on Milvus using the `pymilvus` SDK.

### Installation

Install the required Python libraries from the project root directory:
```bash
pip install -r test/requirements.txt
```

### Scripts Overview

All scripts connect to the local Milvus instance by default (`localhost:19530`).

#### `test/write.py`
- **Purpose**: Initializes the database by creating a collection, defining its schema, creating an index, and inserting sample data.
- **Schema (`book_collection`)**:
    - `book_id`: `INT64`, Primary Key
    - `book_title`: `VARCHAR`
    - `book_embedding`: `FLOAT_VECTOR` (Dimension: 8)
- **Index**: `IVF_FLAT` on the `book_embedding` field.

#### `test/read_all.py`
- **Purpose**: Queries and displays all records currently in the collection in a clean, tabulated format.

#### `test/read.py`
- **Purpose**: Performs a vector similarity search. It generates a random query vector and finds the 2 most similar items in the collection.

#### `test/update.py`
- **Purpose**: Updates an existing entity in the collection using an `upsert` operation. It modifies the record where `book_id` is 3.

#### `test/delete.py`
- **Purpose**: Deletes a specific entity from the collection (the one where `book_id` is 0).

#### `test/drop_collection.py`
- **Purpose**: Completely removes the `book_collection` from the database. This action is irreversible.

### Recommended Execution Flow

To see the full CRUD cycle in action, run the scripts from the project root directory in the following order:

1.  **`python3 test/write.py`**: Creates the collection and populates it with 50 records.
2.  **`python3 test/read_all.py`**: Displays the initial 50 records.
3.  **`python3 test/read.py`**: Executes a similarity search.
4.  **`python3 test/update.py`**: Modifies a record. Run `read_all.py` again to see the change.
5.  **`python3 test/delete.py`**: Removes a record. Run `read_all.py` again to confirm.
6.  **`python3 test/drop_collection.py`**: Deletes the entire collection.

## Appendix: Detailed Milvus Concepts

### How Milvus Works

The fundamental concept behind Milvus is **vector embeddings**.
1.  **Embedding Generation:** Unstructured data (e.g., an image, a paragraph of text, an audio clip) is first transformed into a fixed-size numerical vector by an AI model (e.g., a neural network). This vector is called an embedding, and it captures the semantic meaning of the original data. Similar items will have similar embeddings.
2.  **Vector Storage and Indexing:** These embeddings are then stored in Milvus. Milvus uses specialized indexing algorithms (like IVF_FLAT, HNSW, ANNOY) to organize these vectors in a way that allows for extremely fast similarity searches, even across billions of vectors.
3.  **Similarity Search:** When you want to find similar items, you convert your query item into an embedding. You then send this query embedding to Milvus, which uses distance metrics (e.g., Euclidean distance, cosine similarity) to find the vectors in its database that are closest (most similar) to your query vector.

### Milvus vs. SQL/NoSQL Databases

Milvus is fundamentally different from traditional SQL (relational) and NoSQL databases. The table below summarizes the key differences. The data examples are provided in the list following the table.

| Característica      | Bases de Datos SQL (ej. PostgreSQL) | Bases de Datos NoSQL (ej. MongoDB) | Milvus (Base de Datos Vectorial)                       |
| :------------------ | :------------------------------------ | :----------------------------------- | :----------------------------------------------------- |
| **Dato Principal**  | Estructurado (tablas, filas, columnas) | Semi-estructurado (documentos, JSON) | No estructurado (vectores numéricos/embeddings)         |
| **Ejemplo de Dato** | Ver **Ejemplo 1** abajo               | Ver **Ejemplo 2** abajo              | Ver **Ejemplo 3** abajo                                |
| **Consulta Principal** | Búsqueda exacta, rangos, uniones (joins) | Búsqueda por clave-valor, por documento | **Búsqueda por Similitud** (vecino más cercano)        |
| **Indexación**      | Árboles B, hash                       | Múltiples (árboles B, invertidos)    | Índices vectoriales especializados (IVF, HNSW, etc.)  |
| **Esquema**         | Rígido, predefinido                   | Flexible, dinámico                   | Flexible para metadatos, fijo para la dimensión del vector |
| **Casos de Uso**    | Sistemas transaccionales, informes      | Big Data, aplicaciones web, caché    | **Aplicaciones de IA/ML:** Búsqueda semántica, sistemas de recomendación, reconocimiento de imágenes, chatbots |

#### Ejemplos de Estructura de Datos

1.  **SQL (ej. PostgreSQL):** Datos en tablas con un esquema estricto.
    ```sql
    | id | name  | age |
    |----|-------|-----|
    | 1  | Alice | 30  |
    | 2  | Bob   | 24  |
    ```

2.  **NoSQL (ej. MongoDB):** Datos en documentos flexibles, como JSON.
    ```json
    {
      "user_id": "user123",
      "preferences": {
        "theme": "dark",
        "notifications": true
      }
    }
    ```

3.  **Milvus (Base de Datos Vectorial):** Datos como vectores de alta dimensión (embeddings) con metadatos asociados.
    ```
    | book_id | book_title          | book_embedding (truncado)  |
    |---------|---------------------|----------------------------|
    | 0       | The Great Adventure | [0.12, 0.87, 0.34, ...]    |
    | 1       | Space Odyssey       | [0.91, 0.23, 0.56, ...]    |
    ```

### Why Vector Databases are Essential for AI and Generative AI

Vector databases like Milvus are not just another type of database; they are a foundational component for modern AI and especially Generative AI (GenAI) applications. Here's why:

1.  **Understanding Meaning (Embeddings):** At the heart of AI is the ability to understand and process unstructured data (text, images, audio). Large Language Models (LLMs) and other deep learning models convert this data into high-dimensional numerical vectors called embeddings. These embeddings capture the semantic meaning, context, and relationships within the data. Vector databases are purpose-built to store and efficiently query these embeddings.

2.  **Semantic Search:** Traditional keyword search relies on exact matches or lexical similarity. Vector databases enable **semantic search**, where you can find information based on its meaning, not just keywords. For example, searching for "cars that are good for families" would return relevant car models, even if the exact phrase "family car" isn't present in their descriptions.

3.  **Retrieval Augmented Generation (RAG) for GenAI:** GenAI models (like ChatGPT) are powerful but can suffer from hallucinations (making up facts) or being limited to their training data. RAG is a technique where an LLM first retrieves relevant, up-to-date information from an external knowledge base (often stored in a vector database) and then uses that information to generate a more accurate and contextually relevant response. This significantly enhances the reliability and factual grounding of GenAI outputs.

4.  **Recommendation Systems:** By comparing user preference embeddings with item embeddings, vector databases can power highly personalized recommendation engines for products, content, or services.

5.  **Image and Video Recognition:** Searching for similar images or video segments becomes efficient by comparing their visual embeddings.

6.  **Anomaly Detection:** Deviations from normal patterns can be identified by finding embeddings that are unusually distant from the majority.

7.  **Scalability for AI Data:** AI applications generate and consume vast amounts of vector data. Vector databases are engineered for the unique challenges of storing, indexing, and querying billions or even trillions of high-dimensional vectors at low latency.

In essence, vector databases provide the memory and long-term knowledge base that allows AI models, especially GenAI, to interact with and leverage vast amounts of real-world, unstructured information effectively and intelligently.
